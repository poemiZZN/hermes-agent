# 系列圣经规则（Series Bible Rules）

> 供 `Basics-pro` 技能在跨集生成时调用。
> v4.1 新增：解决单剧 60 集跨集连续性问题——agent 每集生成前读取、生成后更新。

---

## 一、核心机制

系列圣经是**一份随剧集推进持续更新的结构化文档**，存储所有跨集信息。agent 在生成第 N 集前必须读取圣经，生成后必须更新圣经。

```
流程：
  读取圣经（第 N-1 集生成后的最新状态）
    ↓
  生成第 N 集分镜（引用圣经中的角色/场景/道具/剧情线）
    ↓
  更新圣经（记录第 N 集的变化：角色成长、道具状态变更、剧情线推进）
    ↓
  保存圣经供第 N+1 集使用
```

---

## 二、圣经模板

生成第 1 集前，根据剧本创建以下模板。每集生成后更新对应条目。

### 2.1 角色档案

```markdown
## 角色：{完整资产名称}

### 基础信息
- 首次出场：第{X}集
- 当前状态：{存活/死亡/失踪/离场}
- 年龄：{X}岁
- 身高/体型：{描述}

### 外观演进
| 集数 | 服装/外观 | 资产图变更 | 特殊标记（伤痕/饰品/发型变化） |
|------|---------|----------|--------------------------|
| 1 | {初始服装资产名称} | {资产图文件名} | — |
| 15 | {新服装资产名称} | {新资产图文件名} | 右臂新增疤痕（圣经描述，资产图不体现） |
| ... | ... | ... | ... |

**外观变更规则（v4.1 新增）**：
- **轻微变化**（新增疤痕/淤青/发型微调/饰品增减）：仅在圣经中记录，不新建资产图。AI 生成时在资产图基础上叠加圣经描述
- **重大变化**（换装/毁容/断肢/年龄大幅变化）：必须新建资产图 + 新资产名称。圣经中记录"从第 X 集起使用新资产 `{新资产名称}`"，旧资产标记为"已废弃"
- **判断标准**：如果外观变化会导致 AI 仅凭文字描述无法准确还原 → 新建资产图

### 性格弧线
| 集数 | 性格状态 | 关键事件 |
|------|---------|---------|
| 1 | {初始性格描述} | — |
| 15 | {性格变化} | {导致变化的事件} |
| ... | ... | ... |

### 关系演进
| 集数 | 与{角色B}的关系 | 关键事件 |
|------|---------------|---------|
| 1 | {初始关系} | — |
| 20 | {关系变化} | {导致变化的事件} |
| ... | ... | ... |

### 对白特征（详见 character-corpus-rules.md）
- 惯用语：{角色专属口语表达}
- 语速：{快/中/慢}，约{X}音节/秒
- 词汇偏好：{正式/俚语/方言}
- 情绪表达：{愤怒时如何说话/悲伤时如何说话}
```

### 2.2 场景地图

```markdown
## 场景：{完整资产名称}

### 空间信息
- 首次出场：第{X}集
- 最后一次出场：第{X}集（如已废弃）
- 空间布局：{关键特征——如"12根混凝土立柱、3盏日光灯、地面有积水"}
- 不可变特征：{绝对不会改变的元素——如"铁栏杆始终在右侧"}
- 可变特征：{会随剧情改变的元素——如"地面水渍干涸/新增"}

### 出场记录
| 集数 | 时间/光线 | 场景状态变化 | 资产图变更 | 备注 |
|------|---------|------------|----------|------|
| 1 | 黄昏/外 | 初始状态 | — | — |
| 13 | 夜/内 | 地面新增裂纹（第 13 集打斗造成） | 无（圣经描述即可） | — |
| 28 | 黎明/外 | 场景被大火烧毁 | **新建资产图** `学院竞技场 烧毁后` | 重大变化 |
```

**场景变更规则**：
- **轻微变化**（地面裂纹/墙面污渍/物品移位）：仅在圣经中记录，不新建资产图
- **重大变化**（烧毁/坍塌/重建/装修）：必须新建资产图 + 新资产名称。圣经中记录"从第 X 集起使用新资产 `{新资产名称}`"

### 2.3 道具状态表

```markdown
## 道具：{完整资产名称}

### 状态追踪
- 首次出场：第{X}集
- 当前状态：{完好/损坏/丢失/销毁/转移}
- 当前位置：{在谁手中/在哪个场景}
- 当前持有者：{角色名}

### 状态变更记录
| 集数 | 事件 | 状态变化 |
|------|------|---------|
| 1 | 角色A获得 | 状态：完好，持有者：角色A |
| 15 | 战斗中被击碎 | 状态：损坏，碎片散落 |
| 30 | 角色B修复 | 状态：修复但有裂纹，持有者：角色B |
```

### 2.4 剧情线追踪

```markdown
## 剧情线：{线程名称}

### 状态
- 当前状态：{进行中/已解决/休眠/废弃}
- 起始集：第{X}集
- 预计解决集：第{X}集（如已规划）

### 关键节点
| 集数 | 事件 | 线程推进 |
|------|------|---------|

| 30 | {事件描述} | 解决——冲突化解 |
```

## 三、使用规范

### 3.1 生成前读取（Step 0 之后、Step 1 之前）

生成第 N 集（N>1）时，必须先读取圣经，确认以下信息：
1. 本集出场角色当前的外观/性格/关系状态
2. 本集出场场景的当前状态（是否有前期剧集造成的物理变化）
3. 本集涉及道具的当前状态和位置
4. 本集需要推进/回收的剧情线及其当前节点
5. 上一集的结尾事件——确保本集开头衔接

### 3.2 生成后更新（第 8 步之后）

生成第 N 集后，必须更新圣经：
1. 角色外观/性格/关系是否有变化 → 更新角色档案
2. 场景是否有物理变化（破坏/修复/新增）→ 更新场景地图
3. 道具状态是否有变化 → 更新道具状态表
4. 剧情线是否有推进 → 更新剧情线追踪
5. 时间线新增一行 → 更新剧集时间线

### 3.3 连续性自检（每集生成后）

- [ ] 本集出场角色的外观与圣经中记录的最新状态是否一致？
- [ ] 本集出场场景的物理状态与圣经中记录的是否一致？（如第 13 集地面有裂纹，第 14 集不能凭空消失）
- [ ] 本集涉及道具的状态和位置与圣经中记录的是否一致？
- [ ] 本集对话中角色的说话方式与圣经中记录的对白特征是否一致？
- [ ] 本集是否推进了至少一条剧情线？剧情线状态是否需要更新？
- [ ] 本集开头是否衔接了上一集的结尾事件？

## 四、圣经文件管理

### 文件命名
```
{剧名}_series-bible.md
```

### 存储位置
与分镜脚本同目录，或项目根目录。

### 版本控制
每次更新圣经时，在文件末尾追加更新日志：
```markdown
## 更新日志
- 第{N}集生成后更新：{简述变更内容}
```

### 圣经大小控制
60 集后圣经约 3000-5000 行。agent 在读取时优先读取与当前集相关的章节（出场角色、出场场景、活跃剧情线），而非全文。
