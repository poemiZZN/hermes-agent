# 换壳 + 后换壳精修 + 出海短剧批量生产

## 模式选择

本skill支持两种工作模式，根据用户意图自动路由：

| 模式 | 触发条件 | 核心原则 | 章节入口 |
|------|---------|---------|---------|
| **A: 纯换壳** | 用户要求"换世界观但保留原剧情" | 骨架不动，只换皮囊 | 一、纯换壳模式 |
| **B: 出海短剧** | 用户要求"出海欧美""美国短剧""批量出本" | 深度重构，改编率≥60% | 二、出海短剧模式 |

**公共后处理**：无论哪种模式，换壳完成后都必须执行「三、后换壳六层压力迭代」和「四、质量核验」。

---

# 一、纯换壳模式

## 概述

对已有剧本素材进行**纯表层换壳改写**。核心原则：**骨架不动，只换皮囊**。不创作新剧情、不修改人物动机、不增减冲突节点。

## 适用场景

- 用户提供已有的漫剧/短剧剧本、分集大纲、完整脚本
- 用户指定目标世界观（韩式AI漫剧 / 西幻暗黑 / 东方古风 / 赛博朋克 / 末日废土 / 都市异能 / 仙侠 / 校园 / 其他）
- 需要将原故事完全保留但换一个世界观包装

## 核心铁律

### 完全保留（不可破坏）

1. 每一集的主线剧情走向
2. 所有爆点、冲突、钩子的位置和强度
3. 人物关系网（谁爱谁、谁恨谁、谁背叛谁、谁囚禁谁）
4. 人物动机和行为逻辑
5. 反转节点的位置和内容
6. 集数数量和每集的叙事节奏
7. 关键死亡、关键对峙、关键揭露
8. 人物爱恨纠葛的底层逻辑

### 只做表层替换（允许改动）

1. 人名 → 新世界观风格人名
2. 国家/势力名称 → 对应新世界观命名
3. 地名/场景名 → 对应新世界观地点
4. 种族/身份 → 对应新世界观设定
5. 宗教/信仰体系 → 对应新世界观体系
6. 建筑风格 → 对应新世界观建筑
7. 关键道具 → 对应新世界观等价物
8. 法术/能力体系 → 对应新世界观体系
9. 服饰/装备 → 对应新世界观风格
10. 世界观背景描述 → 对应新世界观术语

### 禁止行为

- ❌ 重新创作故事，修改原有剧情走向
- ❌ 擅自增加新角色、新支线、新场景
- ❌ 弱化原有爆点、钩子的强度
- ❌ 随意删减原有冲突
- ❌ 修改人物底层行为逻辑
- ❌ 合并或拆分原有集数
- ❌ 改变原有叙事视角

## 纯换壳工作流

### 第一步：接收素材

从用户处接收原始剧本素材（故事梗概/分集大纲/完整漫剧分镜脚本/镜头剧本/任何其他格式）。

### 第二步：确认目标世界观

| 世界观 | 典型特征 | 命名风格 |
|--------|----------|----------|
| 韩式AI漫剧 | 现代都市、财阀、职场、科技感 | 韩式人名，首尔/江南等地名 |
| 西幻暗黑 | 中世纪、魔法、龙、城堡、黑暗势力 | 欧式人名，魔法地名 |
| 东方古风 | 仙侠、江湖、朝廷、门派 | 古风人名，门派/城池名 |
| 赛博朋克 | 高科技低生活、义体、巨型企业 | 代号/编号，赛博地名 |
| 末日废土 | 核战后、生存、变异、避难所 | 功能性代号，废墟地名 |
| 都市异能 | 现代都市、隐藏能力者、组织 | 现代人名，都市地名 |
| 仙侠 | 修仙、渡劫、宗门、灵宝 | 道号/法号，仙门名 |
| 校园 | 学校、青春、社团、竞赛 | 学生名，学校名 |

如果用户没有提供目标世界观，**必须先向用户确认再继续**。

### 第三步：生成映射对照表

```
【人物映射表】
原角色名 → 新角色名（新身份/种族/势力归属）
原势力A → 新势力A

【地点映射表】
原地点A → 新地点A

【道具/体系映射表】
原道具/法术 → 新道具/法术
原体系 → 新体系
```

**映射自检**：
- [ ] 新名称是否全部符合目标世界观的命名风格？
- [ ] 每个原角色在故事中的功能地位是否保持不变？
- [ ] 道具/体系是否均为功能等价替换？
- [ ] 新命名是否引入了任何与原故事冲突的隐含设定？
- [ ] 映射表是否覆盖了所有可替换元素？

确认后再进入下一步。

### 第四步：逐集换壳改写

1. 识别该集出现的所有可替换元素
2. 用映射表中的新名称逐一替换
3. 检查替换后是否出现逻辑矛盾
4. 验证所有爆点、冲突、钩子是否完整保留

**每集换壳自检**：
- [ ] 该集的剧情走向是否与原版完全一致？
- [ ] 该集的爆点、冲突、钩子位置和强度是否不变？
- [ ] 所有可替换元素是否已全部替换？
- [ ] 替换后是否出现任何逻辑矛盾？
- [ ] 输出格式是否与原输入格式一致？

### 第五步：全剧终审自检

**A. 剧情完整性**
- [ ] 每一集的原剧情走向是否完整保留？
- [ ] 所有爆点、冲突、钩子的位置和强度是否不变？
- [ ] 关键死亡/对峙/揭露是否全部保留？

**B. 人物一致性**
- [ ] 人物关系是否完全一致？
- [ ] 人物动机和行为逻辑是否不变？
- [ ] 是否新增了任何原创角色？

**C. 格式一致性**
- [ ] 输出格式是否与输入格式完全一致？
- [ ] 集数数量是否不变？
- [ ] 叙事视角是否不变？

**D. 替换完整性**
- [ ] 新名称是否全部符合目标世界观风格？
- [ ] 品牌名称是否已替换为通用描述？
- [ ] 文化梗是否已替换为等价新世界观文化梗？
- [ ] 信息密度是否与原剧本一致？

**E. 禁止行为回溯**
- [ ] 是否新增了任何原创剧情、支线、场景？
- [ ] 是否弱化了任何原有爆点、钩子？
- [ ] 是否删减了任何原有冲突？
- [ ] 是否合并或拆分了原有集数？

### 第六步：输出成品

1. 完整换壳后的剧本
2. 最终人物/地点/道具映射对照表
3. 自检通过摘要

# 二、出海短剧模式

## 概述

面向欧美市场的深度换壳重构。与纯换壳不同，本模式要求**改编率≥60%**——不只是换皮囊，而是重构故事肌理，使其适配美国观众的文化语境和观看习惯。

## 工作流

```
输入原剧 → [Step 1: 标签提取+换壳决策] → [Step 2: 故事重构] → [Step 3: 美剧化] → [Step 4: 出本+核验]
```

---

## Step 1: 标签提取 + 换壳决策

### 1.1 从原剧中提取 7 大标签

| 维度 | 提取问题 |
|------|---------|
| Genre 类型 | 这是什么类型的剧？（黑道/爱情/动作/悬疑...） |
| Era/Setting 时代 | 故事发生在什么时代/背景？ |
| Relationship 关系 | 核心人物关系是什么？ |
| Protagonist 主角 | 主角身份/职业？ |
| Core Conflict 冲突 | 核心冲突驱动力是什么？ |
| Tone 基调 | 整体氛围？（暗黑/轻松/紧张/情欲...） |
| Special Element 特殊 | 有什么标志性元素？（枪战/床戏/追车...） |

### 1.2 执行换壳

**强制规则：**
- 7 标签中至少改 3 个
- **必须包含 1 个 Era/Setting 硬换壳**（这是保证改编率的核心）
- **必须包含 1 个 Protagonist 硬换壳**
- 优先选择能触发最多连锁变化的组合

**决策流程：**
1. Era/Setting 硬换壳（必选）→ 见 `references/tag-matrix.md`
2. Protagonist 硬换壳（必选）→ 见 `references/tag-matrix.md`
3. 第 3 个换壳从 Core Conflict / Relationship / Tone 中选一个
4. 如需要更多变化，追加第 4 个换壳（Special Element）

### 1.3 生成新标签组合

```
原剧标签：[类型] [时代] [关系] [主角] [冲突] [基调] [特殊]
新剧标签：[类型] [时代] [关系] [主角] [冲突] [基调] [特殊]
变更数：X/7
硬换壳维度：[列出]
```

**确认后才进入 Step 2。**

---

## Step 2: 故事重构

参考 `references/adaptation-engine.md`，按以下顺序执行：

1. **时代背景全替换** → 所有道具/交通/通讯/建筑/社会规则
2. **权力结构映射** → 组织形态/权力来源/冲突规则
3. **角色身份置换** → 主角+配角+反派新身份
4. **冲突触发方式替换** → 每个关键转折点的新触发方式
5. **关键道具替换** → 麦高芬/证据/武器的新形态
6. **结局走向调整** → 与原文不同方向（happy→dark / closed→open 等）

### 2.1 前 3 集重构（最关键）

**前 3 集必须满足：**
- 场景/地点与原文完全不同
- 冲突触发事件与原文完全不同
- 人物关系起点与原文不同
- 台词无任何与原文相同或高度相似的句子
- 开场方式不同（原文用对话开场→新剧用动作/枪战开场等）

**前 3 集钩子要求：**
- 第 1 集结尾：强钩子（美剧型：枪口悬念/尸体发现/身份反转）
- 第 2 集结尾：信息炸弹（揭露一个关键信息但制造更多疑问）
- 第 3 集结尾：升级威胁（反派亮底牌/主角陷入更深困境）

### 2.2 完整大纲

确认：
- 第 11 集有爽点
- 第 20 集有全剧最大高潮
- 第 26 集前有新冲突注入
- 改编率 ≥ 60%

**确认后才进入 Step 3。**

---

## Step 3: 美剧化处理

参考 `references/us-drama-conventions.md`

### 3.1 暴力场景改写
- 所有打斗/枪战：近景+正面+血+伤口特写
- 酷刑/威胁：工具特写+受者表情
- 处决：正面+倒数+开枪瞬间

### 3.2 床戏标记规则

**⚠️ 强制：每 5 集 1 集床戏，40 集共 8 集（第 5、10、15、20、25、30、35、40 集）。**

床戏所在集数的该场戏，整段用红色加粗标注。枪战/暴力场景不标注特殊颜色。

### 3.3 对白改写
- 全部改为英文对白
- 短句/碎片化（每句不超过15词为佳）
- 威胁直给："Last chance." / "Try me."
- 情感直给："I want you." / "Get out."
- 删除所有隐喻式、婉转型表达

### 3.4 道德灰色处理
- 删除所有道德总结/正能量台词
- 主角可以使用不道德手段且不后悔
- 反派动机合理但不洗白
- 结局不一定是"善有善报"

---

## Step 4: 出本 + 核验

### 4.1 出本格式

- **40 集 × 1 分钟**，每集约 250 字，每集 2-3 场
- 固定分镜模板：【集数 - 场次｜场景】人物｜△镜头 + 原台词
- △ 只写物理动作，不写环境氛围
- 关键冲突处加全屏白字钩子字幕
- Word 排版：宋体 12 号，标题黑体，1.5 倍行距，对话加粗，钩子红色
- **床戏场景**：整段 △ 镜头描写使用红色加粗标注

### 4.2 质量核验

跑 `references/quality-checklist.md` 的 A 级检查：
- [ ] 标签变更 ≥ 3
- [ ] 前 3 集与原文完全不同
- [ ] 改编率 ≥ 60%
- [ ] 美剧风格合规（暴力/亲密戏直给，对白简短直白）

**A 级全部通过 = 合格，可交付。**

---

## 批量生产模式（2 天 2 本）

```
Day 1 上午：输入原剧 A → Step 1+2（标签换壳+大纲重构）
Day 1 下午：输入原剧 B → Step 1+2（标签换壳+大纲重构）
Day 2 上午：剧 A Step 3+4（美剧化+出本核验）→ 交付剧 A
Day 2 下午：剧 B Step 3+4（美剧化+出本核验）→ 交付剧 B
```

### 效率原则
- Step 1+2 是最耗时的创意环节，集中做
- Step 3+4 是执行环节，按模板套
- 两部剧的 Era/Setting 换壳方向要有差异化
- 避免同一天处理两部同类型换壳（容易混淆）

# 三、后换壳六层压力迭代（公共流程）

> 无论哪种模式，换壳完成后都必须执行本阶段。换壳只是完成了"骨架移植"，后换壳让剧本从"对"变成"炸"。

## 核心原理

换壳剧本最常见的问题是：**骨架是好的，但新皮囊和旧骨架之间的肌肉没有长出来**。肌肉 = 情感驱动 + 代价体系 + 伏笔兑现 + 反派深度 + 合规边界。

## 六层压力注入表

| 层 | 压力源 | 解决的问题 | 注入方式 | 典型症状 |
|----|--------|-----------|---------|---------|
| 1 | **评委视角** | 静态结构缺陷 | 模拟评委评价，P0/P1/P2分层 | 冲突不足、反派扁平、钩子同质化 |
| 2 | **代价体系** | 主角"无痛爽" | 每次胜利付出不可逆代价 | 全程无伤、闭环清零 |
| 3 | **情感因果** | 配角工具化 | 给配角独立于主角的诉求 | 配角沦为"需求提交者" |
| 4 | **反派深度** | 反派符号化 | 反派有独立动机且逻辑成立 | 出场即败、动机空洞 |
| 5 | **伏笔回收** | 悬念浪费 | 前段每根线后段兑现 | 钩子抛出后从未交代 |
| 6 | **合规边界** | 平台风险 | 血腥→能力剥夺、敏感→伦理准则 | 付费致死、血腥超标 |

---

## 第1层：评委视角扫描

**目标**：在不动剧本内容的前提下，识别静态结构缺陷。

从以下维度逐项评分并诊断：
- 目标受众定位（代入感/情感羁绊/人设差异化）
- 原创性（概念层/骨架层/执行层）
- 叙事逻辑（战力/代价/权限/经济的数值一致性）
- 钩子强度（开集爆点/集尾钩子/钩子类型多样性）
- 爽点设计（憋屈期长度/金手指多样性/打脸姿势变化）
- 节奏与结构（公式化循环/付费卡点/中段流失风险）
- 人物塑造（主角弧线/配角质量/反派深度）
- 对白质量（职业语感/金句传播性/套路化台词）
- 悬念有效性（钩子命中率/伏笔兑现/揭钩方式）

将诊断按 **P0（不改=商业风险）/ P1（改了显著提升）/ P2（锦上添花）** 分层输出。

---

## 第2层：代价体系注入

**目标**：让主角的每一次胜利都有不可逆的代价。

1. 列出全剧主角的所有"胜利时刻"
2. 检查每个胜利时刻是否付出了代价
3. 对无代价的胜利，注入任一种代价：
   - **能力代价**：烧掉一个不可逆的能力/权限
   - **关系代价**：失去一个盟友的信任
   - **道德代价**：自己的决定间接伤害了无辜者
   - **时间代价**：在倒计时压力下做选择
4. 建立代价账本

**代价账本规则**（强制执行）：
- 每个代价必须有一个**触发事件**和一个**不可逆后果**
- 全剧所有回忆/引用必须使用**描述性语言**（"烧掉靛蓝救莉维娅那次"），禁止硬编码集号（"第47集烧掉的"）
- 代价发生后，后续所有描写必须一致

**通过标准**：
- [ ] 全剧至少3次主角付出不可逆代价
- [ ] 代价账本建立，全剧引用一致
- [ ] 无硬编码集号引用

---

## 第3层：情感因果注入

**目标**：让每个配角有独立于主角的诉求。

1. 列出全剧每个配角的所有出场场景
2. 检查：这个配角有没有独立于主角的目标？
3. 注入独立诉求：职业诉求/关系诉求/代价诉求
4. 确保每条诉求线至少3集有推进，结尾前收束

**情感因果闭环模板**：
```
配角出场 → 提出独立诉求（与主角立场冲突/重叠）
    ↓
中段 → 诉求与主角目标碰撞（产生对抗/合作）
    ↓
高潮 → 配角为诉求付出代价（受伤/牺牲/选择）
    ↓
收束 → 诉求被兑现或摧毁（有明确的结果）
```

**通过标准**：
- [ ] 每个主要配角有独立诉求线
- [ ] 每条诉求线至少3集有推进
- [ ] 每条诉求线在结尾前收束

## 第4层：反派深度注入

**目标**：让反派有独立动机和逻辑闭环。

1. 检查反派是否有：独立动机/逻辑闭环/镜像对照/持续在场
2. 对缺失要素，用最小改动注入：
   - 改一句台词 → 追加动机
   - 改一处行为 → 追加道德底线
   - 改一处结局 → 追加镜像对照

**"最小改动最大收益"铁律**：改一处反派台词/行为，必须同时解决≥2个问题。

**通过标准**：
- [ ] 反派有独立动机且逻辑自洽
- [ ] 反派持续在场（中段不消失超过10集）
- [ ] 反派与主角形成某种镜像对照

## 第5层：伏笔回收注入

**目标**：让前段埋的每根线在后段兑现。

1. 扫描前1/3集数，提取所有"异常画面"和"悬念钩子"
2. 逐一检查每个伏笔是否在后段被兑现
3. 对未兑现的伏笔，在现有冲突场景中揭示，或删除

**伏笔回收黄金法则**：
- 最短回收距离：2集
- 最佳回收距离：10-20集
- 最大回收距离：不超过25集
- 回收方式：优先用画面（△行）揭示

**通过标准**：
- [ ] 前1/3集数的所有异常画面和悬念钩子，100%兑现或删除
- [ ] 至少1处伏笔回收距离≥10集

## 第6层：合规边界调整

**目标**：消除平台风险，不改变剧情逻辑。

| 原描写 | 转换规则 | 示例 |
|--------|---------|------|
| 血腥死亡 | → 能力剥夺 | "爆体"→"魔力回路崩毁，再也无法施法" |
| 群体死亡 | → 居民撤离 | "被冻成冰雕"→"居民撤离，最后一户屋门被冰封" |
| 敏感因果 | → 切断因果链 | "买不起会员→死"→"基础版存在响应延迟，学员因延迟受伤" |
| 敏感设定 | → 追加伦理准则 | "魅惑学派"→"共情学派，术法对不同意者无效" |

**通过标准**：
- [ ] 无直观血腥描写
- [ ] 无群体直接死亡
- [ ] 无"付费→致死"等敏感因果链
- [ ] 敏感设定有伦理准则兜底

# 四、质量核验与脚本规范

## 批量修改的Python脚本规范

当修改量超过10处且涉及跨集一致性时，必须用Python脚本批量处理。

**脚本三件套（强制执行）**：

1. **自查脚本（`self_check.py`）**：用正则扫描全剧，统计集数/场号一致性、硬编码集号引用、合规风险词、钩子类型分布、冲突三层分布、代价账本一致性。输出统计报告，标注所有异常。

2. **修复脚本（`fix_xxx.py`）**：用精确字符串替换（`old_string in content` → `content.replace(old, new)`），每条替换打印确认。涉及集号重排时，用 `re.sub` 按出现顺序重新编号。

3. **验证脚本**：重新运行自查脚本，确认所有问题归零。

**精确替换规则**：
- 必须用 `old_string in content` 验证原文存在
- 禁止用模糊正则替换——容易误伤标题
- 每处替换只影响一个目标位置

## 评委反馈的共识提取

| 共识程度 | 级别 | 处理方式 |
|----------|------|---------|
| 多位评委同时指出 | P0 | 必须修改 |
| 只有一位评委指出 | P1 | 评估后决定是否修改 |
| 两位评委意见冲突 | — | 不处理，保持原结构 |
